# Playbooks

Read the matching playbook at the start of a build, not midway.

| Playbook | Read when |
|---|---|
| `production-playbook.md` | Building any production-grade system, or turning a prototype/demo into one. Design, development, logging and monitoring, testing gate L1–L5, operations, Definition of Done. Stack-agnostic. |
| `ai-project-playbook.md` | Running a client build with AI agents, from the first requirements conversation to local acceptance and handover. Gates G1–G3, agent brief templates; quality bar comes from the production playbook. |
| `ai-project-playbook-lite.md` | The same for small projects: the light track with the minimum gates. |
| `client-handover.md` | Handing a finished build to a client: what is delivered, how it is checked, sign-off. |
| `ai-coding-pitfalls.md` | 28 failure modes of AI-written code with evidence and countermeasures. Review against it before acceptance; use it to brief agents. |

Business-specific case studies and incident mappings live in that business's `docs/`, not here.
